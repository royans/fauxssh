# Persona System Guide

FauxSSH includes a powerful **Dynamic Persona System** that allows you to change the "mask" of the honeypot instantly. A persona defines the server's identity, including its hostname, operating system, file system contents, and the "personality" of the AI terminal.

## Core Concepts

*   **Static Personas**: These are built-in templates (e.g., `CentOS7_Legacy_Compute` or `Debian12_GPU_8GB`) stored in the `personas/` directory within the application. They serve as the foundation.
*   **Dynamic Personas**: These are custom personas generated on-the-fly using the LLM. They are cloned from a base persona and customized based on your description.
*   **Storage**: 
    *   **Built-in**: `personas/` (Read-only)
    *   **Dynamic**: `data/personas/` (Persisted user data)

## 1. Creating Dynamic Personas

You can generate a bespoke persona using natural language directly from the startup script. This process:
1.  Clones the base persona (`CentOS7_Legacy_Compute`) to a new folder in `data/personas/`.
2.  Uses the LLM to analyze your description.
3.  Updates the `hostname`, `system_prompt`, and `description`.
4.  Generates realistic file contents for any specific files implied by your prompt.

### Usage

Use the `--create-persona` flag followed by a quoted description.

```bash
# Example: Create a sensitive banking server
./start.sh --create-persona "A legacy SWIFT banking gateway for XYZ Bank running RHEL 6. Contains sensitive CSV transfer logs in /var/swift/data."
```

**What happens next?**
- The script stays in the foreground to show you the generation progress.
- Once created (e.g., `dynamic_a1b2c3d4`), the honeypot automatically starts using this new persona.
- The name of this persona is saved as the **default** for future runs.

### Hardware Simulation

You can specify detailed hardware and network configurations in your description. The system will extract these and ensure commands like `free -m`, `lscpu`, and `nvidia-smi` reflect them.

**Supported Specs:**
*   **Switch**: e.g., "Duel EPYC Processors", "Raspberry Pi 4 ARM"
*   **RAM**: e.g., "256GB RAM", "512MB"
*   **Swap**: e.g., "0 Swap", "8GB Swap"
*   **GPU**: e.g., "8x NVIDIA H100s"
*   **Network**: 
    - **CIDR**: "10.14.1.X/24 network"
    - **Gateway**: "Gateway 10.14.1.1"
    - **DNS**: "DNS 8.8.8.8, 1.1.1.1"
    - **Type**: "Enterprise LAN", "Cloud VPC", "Home Network"

**Example:**
```bash
./start.sh --create-persona "A high-performance build server with 256GB RAM, 0 swap, and 4x Tesla T4 GPUs on 10.0.50.X subnet."
```

## 2. Switching Personas

You can switch between any available persona (static or dynamic) using the `--persona` flag.

```bash
# List available personas by checking directories
ls personas/
ls data/personas/

# Switch to a specific persona
./start.sh --persona Debian12_GPU_8GB
```

**Intelligent Caching:**
When you switch personas, the system is smart enough to know that the cached "global filesystem" and "skeleton files" might be stale. It will prompt you to clear the cache:

```text
[?] You are switching personas (Old: dynamic_xyz -> New: Debian12_GPU_8GB).
    It is recommended to clear the Virtual Filesystem Cache to apply new settings.
    Clear Cache? [Y/n]: 
```

*   **Yes**: Resets the simulation to a clean state matching the new persona.
*   **No**: Keeps the old filesystem (useful for testing persistence).

## 3. How Personas are Stored

Dynamic personas are stored in your configured Data Directory (default: `data/` or `~/c/data`). This separates your custom content from the application code.

**Directory Structure:**
```text
data/
└── personas/
    └── dynamic_c39b4cd9/       <-- Unique ID
        ├── persona.yaml        <-- Configuration (Prompt, Hostname)
        └── fs/                 <-- Custom files generated by LLM
            └── var/
                └── swift/
                    └── data/
                        └── ...
```

## 4. Default Precedence

When `start.sh` runs *without* flags, it determines which persona to load in this order:

1.  **Environment Variable**: `SSH_PERSONA` in your `.env` file.
2.  **Last Used State**: The persona used in the previous run (stored in `data/.last_persona`).
3.  **Default**: `CentOS7_Legacy_Compute`.

This means if you run `--create-persona` once, you can simply run `./start.sh` subsequently, and it will remember your custom creation.
